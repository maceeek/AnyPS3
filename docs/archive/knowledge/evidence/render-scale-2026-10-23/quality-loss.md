## Confirmed source mechanisms

1. **General surface merge loses old visual history.** `rsx_graphics.py:1338–1421`, `Session::rebind_merge`: for a nondiscard bind, upload guest background, pack each dirty `old.image` with `graphics_pack_readback` at1393, copy intersecting physical byte runs into a native packed buffer, then unpack at1412. The source is the native parent, never its child. `rsx_vk_upload.py:70` unconditionally calls `graphics_visual_sync`; `rsx_vk_graphics.py:614–629` nearest-blits the whole native image to the child. Any subpixel information in replaced owners disappears from the new visual image, including covered regions that had been rendered at higher resolution. Dirty partial remainders retain old paired images, but do not restore detail in the new merged image. A discard merge followed by full clear does not need prior visual history and must not be classified as a quality loss.
2. **Equal-footprint rebind has the same collapse.** `rsx_graphics_rebind.py:37–41` native pack→unpack; its physical-byte proof is sound for native semantics but says nothing about a high-resolution companion. Format/depth/layout changes can therefore lose detail without host access.
3. **Unsupported RTT conversions intentionally reconstruct.** `rsx_graphics_rtt.py:159–162,196`: only aligned same-texel typed linear mappings set `scale_visual`. BC, swizzle, typeless float/depth, shifted-byte and other format reinterpretations use native conversion; `rsx_vk_graphics.py:1114–1116` then syncs the output child. `graphics_aspect_image` (`rsx_vk_graphics.py:692–718`) extracts native data and syncs its child too. These can destroy visual scene/depth history if consumed downstream, but their current role must be measured.
4. **Native uploads and missing-owner paths are inherently native.** `upload_surface` (`rsx_graphics.py:1429–1446`) goes through unpack+sync. Ordinary host-backed textures need not contain higher-resolution information; those copies alone are not defects. Raw compute alias raster (`rsx_graphics_alias.py`, `draw_alias`) flushes/clears surfaces and computes guest-resolution bytes. This is distinct from `rebind_merge`/`alias_merges`; do not conflate the two from names.

## Paths that already preserve the companion

`bind` compatible UNORM↔SRGB aliases (`rsx_graphics.py:1560–1567`) call paired `graphics_copy` (`rsx_vk_graphics.py:734–744`), preserving child pixels byte-for-byte. Exact surface-to-surface copy does likewise. Sample-grid1↔2 shader (`rsx_graphics.py:1500–1507`) and supported typed RTT use child sources and physically enlarged output; direct RTT returns the paired source image. These preserve available detail, but cannot reconstruct information lost earlier.

Async flip and synchronous scanout (`rsx.py:396–403,449–465`) find a full native1280×720 one-sample format8 surface matching the display target, then select its child. SRGB scanout copies remain paired. `rsx_vk_present.py:176` passes actual child extents; WSI display at118–138 blits them to actual swapchain extent with nearest filtering. If a compositor/swapchain ultimately presents at1280×720, that is a further downsample, so log actual destination extent too. Neither selecting a child nor executing additional late full-screen draws guarantees that its source retained scene detail.

## Ranked hypotheses and minimal decisive diagnostic

**Leading hypothesis:** a full-scene nondiscard merge/equal-footprint transition or unsupported RTT conversion occurs after high-resolution scene rendering and before final composition, resetting the main image to native quality. This is directly plausible from source and recurring counters, but not yet a confirmed root cause of the user's observation. Alternative: final image retains detail but display size/compositor or naturally soft postprocessing masks it. Flat host-invalidations weakens the earlier CPU-write hypothesis for the steady window.

Record a short operator-triggered window of1–2 steady frames, not startup-capped MERGE_TRACE output. Assign stable image IDs plus generation/command sequence; include parent/child IDs, guest offset/base/pitch/extent/format/samples/depth, physical layout identity, and current display buffer target. Emit:

- Every native→visual sync with reason/caller, whole-image versus region, destination image ID and whether it previously held high-resolution history.
- Merge/rebind source IDs and covered physical-byte ranges, destination ID, discard flag, and retained remainders; RTT source/output IDs, typed gate outcome and exact failed condition.
- Geometry/full-screen draw target and sampled-image IDs; copy edges; final scanout selected ID, native/child extent, swapchain extent. A boolean “has visual draws” is insufficient: late HUD geometry can coexist with a collapsed world image.

Backtrack dependencies from final scanout to the last scene geometry. Capture matched pre-loss source child and post-loss destination child only at implicated boundaries, plus native and final child from the same frame. Examine world-edge/textured-geometry crops and within-native-cell variation against nearest-upscaled native. Nonzero variation alone is not sufficient (HUD/postprocess can create it). Existing MERGE_TRACE is capped early at200 lines and lacks image lineage, so enabling it unchanged may miss the playable scene.

## Smallest sound fix once the responsible mapping is identified

Leave the native pack/merge/unpack and guest reports/readback unchanged. Add an independent visual transfer after native destination initialization. Reuse the proven physical-byte intersection mapping to construct a **whole-texel** destination→source mapping, including source plane and subpixel coordinate. For complete same-format cells supplied by one valid old owner, transfer directly from its child; untouched destination cells retain appropriate paired background. Preserve parent+child lifetimes through deferred recorder/barrier boundaries. For mixed-byte cells, incompatible formats, or genuinely CPU-written background, retain explicit native reconstruction for those cells only; never manufacture high-resolution values from byte fragments.

At integer2×, map each destination native cell's2×2 subcells into the corresponding source native cell/plane. Tiling and swizzle require deriving the map from actual physical ownership/readback plans, not assuming pitch arithmetic. Depth/stencil require separate compatible aspect handling. Reuse full paired copies for bijective identity layouts. Equal-footprint rebind needs a permutation of native cells/planes, not a scaled byte buffer. Extend supported typed RTT only when the conversion has a defined whole-texel visual mapping; typeless depth/color can need an explicit high-resolution per-texel codec rather than native aspect extraction.

Initialize native background as today, suppress the unconditional **whole-child** sync only when a complete replacement visual plan has been certified, and preserve native fallback for unsupported cells. Planning/preflight must precede dependent command recording; diagnostics should report coverage fraction and reason for remaining reconstructed cells. Start with the actual final-scene transition rather than a general alias rewrite.

Regression: fill source child subcells with values absent from native source, merge/rebind complete and partial overlapping owners, verify exact independent native bytes and preserved child values for supported cells, unchanged background/remainders, sample-plane ordering, tiling and lifetime across async submission. Then same-frame real-game crops must demonstrate retained geometric detail through final composition. FPS and image dimensions are separate acceptance axes.
