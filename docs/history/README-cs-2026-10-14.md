# AnyPS3

Experimentální základ nástroje pro statickou rekompilaci PS3 programů na PC.
První cílová hra projektu je **Ratchet & Clank: A Crack in Time**.
Obraz vydání BCES00511 01.00 je kompletní, jeho CRC ověřené a všech 811
souborů rozbalených. Nový příkaz `recompile-program` překládá také start procesu,
volání, větvení a část inicializace hry. Společný nativní program s původními
knihovnami firmwaru nyní inicializuje GCM, konfiguruje dva obrazové buffery
1280 × 720 a spouští šest staticky přeložených SPU kontextů. Pět z nich
vykonává původní herní správce úloh. Fungují skutečné DMA přenosy, atomiky,
uspávání a probouzení. Nativní vstupní služba používá SDL2; grafický runtime
obsluhuje inicializační FIFO a skutečnou VRAM. Engine dokončil generování textur,
prošel inicializací herních dat a provedl první vlastní Vulkan clear:
960 × 704, dlaždicové ARGB8 a Z24S8 plochy se dvěma vzorky.
Backend čte výsledné pixely zpět do VRAM. Syntetická diagnostika ověřila 57 600 pixelů
přes Lavapipe; [postup a omezení](../vulkan-rendering.md).
Hra dokončila první čtyři headless výměny bufferů; zachycené snímky jsou
zatím černé. **Menu, shadery, kreslení geometrie a hratelnost zatím chybí.**
FIOS čte skutečné herní archivy a vytváří diskovou cache. Původní SPU kód
nativně rozbalil celý `game.toc` (136 620 bajtů), ověřený bajt po bajtu
proti nezávislé dekompresi. Výsledky předává přes DMA a mailbox události PPU.
Podrobnosti a reprodukci shrnuje [milník načítání](../ratchet-acit-loading-milestone.md).
Nejnovější stav je v [postupu směrem k menu](../menu-progress.md).
Předchozí milník popisuje [zpráva o nativním startu](../ratchet-acit-startup.md).
Starší důkazy jsou ve [zprávě o paměti](../ratchet-acit-memory-milestone.md)
a [prvním rozboru EBOOT](../ratchet-acit-milestone.md).

## Vyzkoušení bez herních dat

Potřebujete Python 3.11+ a pro sestavení výsledku kompilátor C++17 (`c++`).
Z kořene projektu lze vše spustit bez pip, instalace balíčků a připojení k síti:

```bash
mkdir -p build
python3 -m anyps3 demo -o build/answer42.elf
python3 -m anyps3 inspect build/answer42.elf
python3 -m anyps3 recompile build/answer42.elf -o build/answer42.cpp
c++ -std=c++17 -O2 build/answer42.cpp -o build/answer42
./build/answer42
```

Výsledek: `r3=42`. Vstup obsahuje čtyři skutečně zakódované instrukce PowerPC:
`li r3,40; li r4,2; add r3,r3,r4; blr`. Jde o náš syntetický ELF s PS3
rozložením vstupního deskriptoru, nikoli o dump hry či kompletní PS3 homebrew.
Assemblerová podoba je v [examples/answer42.ppu.s](../../examples/answer42.ppu.s).

Výstupní soubory musí být nové. Příkazy `demo` a `recompile` odmítají přepsat
existující soubor, včetně vstupu. Při opakování použijte jiný název či složku.
Nástroj sám nepouští kompilátor ani výsledný program.

## Co funguje

- `inspect`: ELF32/ELF64 v obou pořadích bajtů, hlavička, programové segmenty,
  kontrola rozsahů a zarovnání, SHA-256 a textový nebo JSON výstup.
- PS3 PPU vstupní deskriptor: dvě big-endian 32bitové hodnoty pro adresu kódu
  a TOC (`r2`). Přímá adresa kódu vyžaduje explicitní `--entry-kind code`.
- `recompile`: průchod dosažitelným kódem jedné funkce, generování C++
  a samostatného testovacího `main`. Podporuje `addi`, `addis`, `ori`, `oris`,
  `xori`, `xoris`, `add`, `subf`, `and`, `or`, `xor`, `b`, `ba` a přesný `blr`.
  Aritmetické a logické varianty měnící CR/XER a volání nejsou podporované.
- Paměťové instrukce `lwz`, `lbz`, `lhz`, `lha`, `stw`, `stb`, `sth`, `ld`,
  `std` včetně update forem a `lwa`. Testovací runtime mapuje ELF segmenty,
  nuluje BSS, vytváří zásobník a kontroluje rozsahy a přístupová práva.
- Nepodporovaná instrukce zastaví překlad s adresou a kódem instrukce.
  Překlad nesmí potichu vynechat nepodporované chování.
- `recompile-program`: statický graf více funkcí, CR/XER, LR/CTR, přímá
  i předem zahrnutá nepřímá volání, indexovaná paměť, část VMX a floating point.
  `--process-entry` sestaví argumenty procesu, TLS a zapne omezené nativní
  systémové služby. `--diagnostic` vloží do nepodporovaných míst explicitní
  zastavení s nenulovým návratovým kódem; instrukce nikdy nepřeskočí.
- Profil cílové hry může ověřit SHA-256 vstupu. Nevyplněný profil nikdy
  neoznačí libovolný vstup za ověřenou kopii Ratcheta.
- `recover-zip`, `disc-inventory`, `disc-extract`: obnova ISO ze ZIP/ZIP64
  i bez centrálního adresáře, ISO9660 inventář a extrakce včetně souborů
  rozdělených do více extentů. Částečná extrakce vyžaduje `--allow-partial`.
- `sfo`: čtení identity hry z PARAM.SFO.
- `unself`: převod podporovaného retail APP SELF na analytický ELF, s kontrolou
  HMAC převzatých segmentů. Vyžaduje explicitní soubor parametrů klíče
  a volitelný balíček `cryptography`; klíče nejsou součástí projektu.
  `--allow-prx` povoluje extrakci APP PRX pro další analýzu.
- `python -m anyps3.firmware`: ověřená offline extrakce PUP.
  `python -m anyps3.build_game`: experimentální společný AOT obraz Ratcheta
  a vybraných původních knihoven s relokacemi a vazbou exportů.
- `analyze`: sekce, deskriptory OPD, importy/NID, vložené SPU ELF a přehled
  prvních překážek při překladu jednotlivých vstupů funkcí.

```bash
python3 -m anyps3 inspect build/answer42.elf --json
python3 -m anyps3 recompile build/answer42.elf \
  --entry 0x10000 --entry-kind code -o build/direct-entry.cpp
```

`inspect` úspěšně vypíše i podporovaný ELF jiného procesoru. Jeho úspěch není
potvrzením rekompilovatelnosti. JSON uvádí `schema_version: 1` a adresy jako
čísla. Návratový kód 0 znamená dokončení daného příkazu, 1 chybu vstupu nebo
nepodporovanou funkci a 2 chybu syntaxe CLI.

## Současné hranice

Překladač přijímá pouze big-endian ELF64 PowerPC64 typu `ET_EXEC` s adresami
v 32bitovém prostoru PS3. Vygenerovaný testovací program inicializuje registry
na nulu a `r2` na TOC. Pokud funkce používá paměť, navíc nastaví `r1` na
syntetický zásobník a načte segmenty z původního analytického ELF.
`blr` zde znamená návrat z testované funkce do testovacího `main`.

Paměťový program se spouští jako `./harness cesta/k/puvodnimu.elf`.
Kontroluje velikost a CRC32 proti vstupu při generování; jde o ochranu před
záměnou souboru, nikoli kryptografické ověření. Mapa je omezena na 512 MiB,
zásobník má 1 MiB a neobsahuje argumenty procesu ani TLS. Přístupy přes hranici
segmentu a zápis do kódu se odmítají. Registry argumentů funkce zůstávají nulové;
funkce vyžadující platný objekt či inicializaci enginu proto mohou selhat.

Výše popsaný jednoduchý harness patří příkazu `recompile`. Rozšířený
`recompile-program --process-entry` inicializuje argumenty procesu a TLS;
konkrétní možnosti a omezení popisuje [zpráva o startu](../ratchet-acit-startup.md).
Stále chybí většina systémových služeb, úplná ISA PPU/SPU, úplný životní cyklus
vláken, obecné dynamické načítání PRX, kreslení RSX geometrie a zvuk. Vstup přes SDL2
má ověřené tlačítkové a analogové ovládání i hotplug na virtuálním zařízení;
pohybové senzory a vibrace chybí. Běh herního startu vyžaduje SDL2 pro Linux.
PPU již používá kooperativní plánovač s oddělenými registry a TLS. `inspect`/`recompile` přijímají ELF; podporovaný SELF je
nutné nejdříve zpracovat příkazem `unself`. Výsledkem je analytický obraz
s ověřenými load segmenty, nikoli přesná kopie všech bajtů původního ELF.
Nepřevzatá data mimo segmenty se vyplní nulami; původní podpis ECDSA se neověřuje.

Částečný ZIP neposkytuje ověřenou CRC celého ISO. Dostupnost souboru v obrazu
není důkaz integrity. Nástroje rozlišují tyto stavy v JSON reportech.

## Ověření

```bash
python3 -m unittest discover -s tests -v
```

Sada obsahuje 156 testů včetně volitelného Vulkan testu. Testy zahrnují poškozené a zkrácené ELF, oddělení souborových a virtuálních
adres, BSS, interpretaci OPD, odmítnutí nepodporovaných instrukcí a bezpečné
zachování existujících souborů. Integrační test sestavuje a spouští 15
syntetických programů, které ověřují například znaménkové rozšíření,
přetečení a rozdílný význam registru `r0` v aritmetice a logických operacích.
Bez `c++` je tento integrační test výslovně přeskočen.
Paměťové integrační testy navíc ověřují endianitu, šířku a znaménko loadů,
update formy, zachování starého SP při `stdu`, BSS, chyby mapování a záměnu ELF.
Testy SELF používají vlastní syntetické klíče a data; bez `cryptography` jsou
výslovně přeskočeny. Žádný test nevyžaduje herní soubory.
Další nativní testy ověřují překrývající se statické SPU overlaye, SNR,
sloučenou FP aritmetiku, VMX, životní cyklus SDL ovladače a pořadí FIFO RSX.
Test SDL vstupu vyžaduje dostupnou sdílenou knihovnu SDL2.
Vulkan test vyžaduje hlavičky, loader a funkční ICD (stačí Lavapipe);
ověřuje skutečný render pass, readback a zachování okolní VRAM.

Volitelně lze nástroj instalovat přes `python3 -m pip install -e .`, pokud je
k dispozici pip a setuptools; potom funguje i příkaz `anyps3`.
