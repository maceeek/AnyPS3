# AnyPS3

An experimental foundation of a tool for static recompilation of PS3 programs to PC.
The project's first target game is **Ratchet & Clank: A Crack in Time**.
The image of release BCES00511 01.00 is complete, its CRC verified and all 811
files extracted. The new command `recompile-program` also translates the process start,
calls, branching and part of the game's initialization. A shared native program with the original
firmware libraries now initializes GCM, configures two 1280 × 720 display buffers
and launches six statically translated SPU contexts. Five of them
run the original game task manager. Real DMA transfers, atomics,
sleeping and waking work. The native input service uses SDL2; the graphics runtime
handles the initialization FIFO and the real VRAM. The engine finished texture generation,
passed the game data initialization and performed the first own Vulkan clear:
960 × 704, tiled ARGB8 and Z24S8 surfaces with two samples.
The backend reads the resulting pixels back into VRAM. A synthetic diagnostic verified 57,600 pixels
through Lavapipe; [procedure and limitations](../vulkan-rendering.md).
The game completed the first four headless buffer swaps; the captured frames are
so far black. **The menu, shaders, geometry drawing and playability are still missing.**
FIOS reads real game archives and creates a disk cache. The original SPU code
natively unpacked the entire `game.toc` (136,620 bytes), verified byte by byte
against an independent decompression. It passes the results via DMA and mailbox events to the PPU.
Details and reproduction are summarized in the [loading milestone](../ratchet-acit-loading-milestone.md).
The latest state is in [progress toward the menu](../menu-progress.md).
The previous milestone is described by the [native start report](../ratchet-acit-startup.md).
Older evidence is in the [memory report](../ratchet-acit-memory-milestone.md)
and the [first EBOOT analysis](../ratchet-acit-milestone.md).

## Trying it without game data

You need Python 3.11+ and, to build the result, a C++17 compiler (`c++`).
From the project root everything can be run without pip, package installation and a network connection:

```bash
mkdir -p build
python3 -m anyps3 demo -o build/answer42.elf
python3 -m anyps3 inspect build/answer42.elf
python3 -m anyps3 recompile build/answer42.elf -o build/answer42.cpp
c++ -std=c++17 -O2 build/answer42.cpp -o build/answer42
./build/answer42
```

Result: `r3=42`. The input contains four really encoded PowerPC instructions:
`li r3,40; li r4,2; add r3,r3,r4; blr`. It is our synthetic ELF with the PS3
layout of the entry descriptor, not a game dump or a complete PS3 homebrew.
The assembler form is in [examples/answer42.ppu.s](../../examples/answer42.ppu.s).

Output files must be new. The commands `demo` and `recompile` refuse to overwrite
an existing file, including the input. When repeating, use a different name or folder.
The tool itself does not run the compiler or the resulting program.

## What works

- `inspect`: ELF32/ELF64 in both byte orders, header, program segments,
  checking of ranges and alignment, SHA-256 and text or JSON output.
- PS3 PPU entry descriptor: two big-endian 32-bit values for the code address
  and TOC (`r2`). A direct code address requires an explicit `--entry-kind code`.
- `recompile`: traversal of the reachable code of a single function, C++ generation
  and a standalone test `main`. Supports `addi`, `addis`, `ori`, `oris`,
  `xori`, `xoris`, `add`, `subf`, `and`, `or`, `xor`, `b`, `ba` and an exact `blr`.
  Arithmetic and logical variants that change CR/XER and calls are not supported.
- Memory instructions `lwz`, `lbz`, `lhz`, `lha`, `stw`, `stb`, `sth`, `ld`,
  `std` including update forms and `lwa`. The test runtime maps ELF segments,
  zeroes BSS, creates a stack and checks ranges and access rights.
- An unsupported instruction stops the translation with the address and the instruction code.
  The translation must not silently omit unsupported behaviour.
- `recompile-program`: static graph of multiple functions, CR/XER, LR/CTR, direct
  and pre-included indirect calls, indexed memory, part of VMX and floating point.
  `--process-entry` builds the process arguments, TLS and turns on limited native
  system services. `--diagnostic` inserts into unsupported places an explicit
  stop with a nonzero return code; it never skips an instruction.
- A target game profile can verify the SHA-256 of the input. An unfilled profile never
  labels an arbitrary input as a verified copy of Ratchet.
- `recover-zip`, `disc-inventory`, `disc-extract`: ISO recovery from ZIP/ZIP64
  even without a central directory, ISO9660 inventory and extraction including files
  split into multiple extents. Partial extraction requires `--allow-partial`.
- `sfo`: reading the game identity from PARAM.SFO.
- `unself`: conversion of a supported retail APP SELF to an analytical ELF, with a check of
  the HMAC of the segments taken over. Requires an explicit key parameter file
  and the optional package `cryptography`; keys are not part of the project.
  `--allow-prx` permits extraction of APP PRX for further analysis.
- `python -m anyps3.firmware`: verified offline PUP extraction.
  `python -m anyps3.build_game`: experimental shared AOT image of Ratchet
  and selected original libraries with relocations and export binding.
- `analyze`: sections, OPD descriptors, imports/NIDs, embedded SPU ELFs and an overview of
  the first blockers in translating individual function entries.

```bash
python3 -m anyps3 inspect build/answer42.elf --json
python3 -m anyps3 recompile build/answer42.elf \
  --entry 0x10000 --entry-kind code -o build/direct-entry.cpp
```

`inspect` successfully prints even a supported ELF of another processor. Its success is not
a confirmation of recompilability. The JSON states `schema_version: 1` and addresses as
numbers. Return code 0 means completion of the given command, 1 an input error or an
unsupported function, and 2 a CLI syntax error.

## Current boundaries

The translator accepts only big-endian ELF64 PowerPC64 of type `ET_EXEC` with addresses
in the 32-bit PS3 space. The generated test program initializes registers
to zero and `r2` to the TOC. If the function uses memory, it additionally sets `r1` to
a synthetic stack and loads the segments from the original analytical ELF.
`blr` here means return from the tested function to the test `main`.

The memory program is run as `./harness path/to/original.elf`.
It checks the size and CRC32 against the input at generation time; this is a safeguard against
swapping the file, not a cryptographic verification. The map is limited to 512 MiB,
the stack is 1 MiB and contains neither process arguments nor TLS. Accesses across the boundary
of a segment and writes into code are rejected. The function's argument registers stay zero;
functions requiring a valid object or engine initialization may therefore fail.

The simple harness described above belongs to the `recompile` command. The extended
`recompile-program --process-entry` initializes the process arguments and TLS;
the specific options and limitations are described in the [start report](../ratchet-acit-startup.md).
Most system services, the full PPU/SPU ISA, the complete thread lifecycle, general dynamic
PRX loading, RSX geometry drawing and sound are still missing. SDL2 input
has verified button and analog control and hotplug on a virtual device;
motion sensors and vibration are missing. The game start run requires SDL2 for Linux.
The PPU already uses a cooperative scheduler with separate registers and TLS. `inspect`/`recompile` accept ELF; a supported SELF
must first be processed with the `unself` command. The result is an analytical image
with verified load segments, not an exact copy of all bytes of the original ELF.
Data not taken over outside the segments is filled with zeros; the original ECDSA signature is not verified.

A partial ZIP does not provide a verified CRC of the whole ISO. The availability of a file in the image
is not evidence of integrity. The tools distinguish these states in JSON reports.

## Verification

```bash
python3 -m unittest discover -s tests -v
```

The suite contains 156 tests including the optional Vulkan test. The tests include corrupted and truncated ELFs, separation of file and virtual
addresses, BSS, interpretation of OPD, rejection of unsupported instructions and safe
preservation of existing files. The integration test builds and runs 15
synthetic programs that verify, for example, sign extension,
overflow and the different meaning of register `r0` in arithmetic and logical operations.
Without `c++` this integration test is explicitly skipped.
Memory integration tests additionally verify endianness, load width and sign,
update forms, preservation of the old SP in `stdu`, BSS, mapping errors and ELF swapping.
The SELF tests use their own synthetic keys and data; without `cryptography` they are
explicitly skipped. No test requires game files.
Further native tests verify overlapping static SPU overlays, SNR,
fused FP arithmetic, VMX, the SDL controller lifecycle and the order of the RSX FIFO.
The SDL input test requires an available SDL2 shared library.
The Vulkan test requires headers, a loader and a working ICD (Lavapipe is enough);
it verifies a real render pass, readback and preservation of the surrounding VRAM.

Optionally the tool can be installed via `python3 -m pip install -e .` if
pip and setuptools are available; then the `anyps3` command also works.

## Further development

[Architecture and milestones](../architecture.md) describe further work independent
of a game dump and the subsequent verification on Ratchet. The profile
[ratchet-acit.json](../../profiles/ratchet-acit.json) contains the verified identity
of the release and the hash of our analytical ELF. The synthetic demo does not match this profile.

AnyPS5 serves as inspiration for the way of use. This prototype contains neither
its code nor the code of ps3recomp/RPCS3 and does not yet connect any of these projects
as a dependency. Their technical sources are listed in the documentation.
