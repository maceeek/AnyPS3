## `sys_timer_usleep` put the whole emulator to sleep (verified, fixed in 314)

- 313p after skipping the intro video (virtual START, `digital1=0008`; the video `mol_tease_fmv.bik` ran at ~1.7 fps,
  SPU ~82 M instr./s) briefly 54–59 flips/s (simple screen, ~2 draws/flip), then a loading screen at ~12% CPU:
  profile `cpu.prof.1` 66% in `syscall()`, in the last 200 k log lines 181,798× syscall 141.
- Cause (code `services.py` case 141 up to 313): `std::this_thread::sleep_for` on the single host thread → all PPU threads
  sleep (both emulated HW threads), including the thread the game is waiting for. **Verified from RPCS3 @ ffba2bf0
  `rpcs3/Emu/Cell/lv2/sys_timer.cpp:450-483`:** a non-zero usleep = `lv2_obj::sleep(ppu)` + `wait_timeout` (only the
  caller sleeps), 0 = host yield.
- Fix: case 141 = a per-thread timed wait like `sys_timer_sleep` (142, `sync_ext_wait` kind 12), the repeated
  syscall returns 0; `usleep(0)` = `reschedule`; the idle scheduler (`threads.py`) sleeps until the nearest deadline
  (max 1 ms) instead of a fixed 1 ms. The diagnostic ceiling `ANYPS3_SLEEP_BUDGET_US` and the stop for > 1 s are unchanged.
  Test `tests/test_timer_usleep.py` (independent expectation: 0.5 s sleep → peer runs within 100 ms; return 0 after expiry;
  fails on the old implementation). Snapshot `local/ratchet/source-snapshot-314`.

## 320: aligned guest backings (2026-10-16 ~20:00)

- **Verified cause of allocator-edge:** the `allocator_edge` details of 319 have `owner_size=261095424 owner_mod_4k=16`:
  the `std::vector` of RSX local memory (glibc mmap chunk) starts at a host address ≡ 16 (mod 4096), so the first host page
