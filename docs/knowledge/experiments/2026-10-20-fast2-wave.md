GPU clocks during 470a: mostly P8 210 MHz and P3 ~950 MHz, short P0 2.6–2.9 GHz bursts (utilization ≤ 40%).

**Derived:** the cloud round gives +31% FPS in the game; the GPU time per frame fell by ~18 ms, consistent with the MSAA plane
runs hypothesis of the cloud record (not yet separated by an A/B run). Fewer guest instructions per frame on thread 1 at a
higher ns/instr means less busy-waiting (spin hints / SPU parking), not a slower PPU.
**Derived — VSYNC quantization:** in mode 0 the game flips on vblank (59.94 Hz), so the frame rate moves in steps; a median
of exactly 29.97 means most frames take two vblanks. 60 FPS needs every per-frame path (RSX worker CPU, GPU, main thread,
SPU jobs on the critical path) under 16.7 ms, with headroom ~13 ms. The RSX worker (22.9 ms) is the first limit; the main
thread (15.8 ms busy) is at the budget edge; the GPU (13 ms at low clocks) is inside it.

## Wave 1 results (Sonnet 5.5 xhigh agents, stopped at a milestone on user instruction ~09:30–09:45)

Full handoffs: `local/ratchet/work/{gpufast,rsxcpu,critpath}/RESULT.md`; reviews `local/ratchet/work/_reviews/`.

- **RSXCPU (verified, run 502a):** rsx_worker **22.87 → 18.06 ms/frame** in the level, correct image, no STOP. Main cause: vertex input
  reads with shared `Range::read` leases instead of an exclusive `GpuPages` claim + `membarrier` per draw (c49974c), plus vertex-range
  grouping (vertex bytes 21.9 → 6.75 MB/frame) and DEVICE_LOCAL memory recycling (5dd6622). The Sol finding "torn geometry under a
  concurrent bulk writer" was rebutted with a test (`ordered_bulk_writes_`): writes ordered by labels/semaphores before the draw are
  seen completely and the snapshot completes before any later label is published; only unordered races (undefined on hardware too) change.
  Remaining RSX costs: 47k slow leases/frame from FIFO loads, 5 alias readbacks/frame (`rebind_merge` rejects a 1-byte/pixel target),
  long tail.
- **GPUFAST (verified on the replay, game build 480 pending):** GPU time depends on the clock state: the same replay frame takes ~103 ms at
  P8 and ~10.5 ms at P0; the game is fed in bursts and stays at P8/P3. Batch prelude (staging→device copies, ~37 MB/frame) moved to the
  dedicated transfer queue with a timeline semaphore: graphics-queue time at P0 10.6 → 8.2 ms/frame, VRAM hash unchanged.
  Negative results: barrier de-duplication, eliding occlusion queries (no gain), layered/multiview MSAA.
- **CRITPATH (verified):** wall-clock attribution of the main thread (520b): ~50% sleeping in the game's frame-pacing wait
  (`0x5c56d4`, `usleep(50)` loop; hypothesis: polls the RSX flip status), ~6 ms/frame SPU-job waits (engine-counter wait `0x696c10`,
  job-flag wait `0x5564d4`), ~10 ms/frame real work. SPU lane `0x100` (CellSpursKernel0, ~70% of SPU instructions) runs ~17 ms per
  33.4 ms frame → **at 60 FPS it is at the limit and must get ~2× faster**. `ppu_schedule` 285 → 95 ns per call (coordinator −1 ms/frame,
  total busy unchanged: the saving goes into guest spinning). Timer slack 1 ns refuted (+1.3 ms busy) → opt-in only.

Integration branch `integ/471` = main + the three branches (one trivial conflict in `anyps3/vulkan.py` device teardown: both
`vkDestroyCommandPool(transfer_pool)` and `release_memory_cache(device)` kept). Build 471 queued; Sol interaction review running.
