## Finding 1 — geometry/index reuse (H5) made the game 4× slower (verified)

- **Observation:** 1036 (cloud tip, all defaults, walking wrapper with recorder on) walked at **8.57 FPS** (1036w1, cold)
  and **10.96 FPS** (1036a1, warm); RSX worker 97.8 / 74.8 ms per frame. Per-frame host stages against 1034a2:
  `indices` 0.48 → 34.1 ms, `tail` (vertex input read) 0.66 → 53.7 ms; every other stage unchanged
  (`PERF RSX_STAGES`, measurement window only).
- **Mechanism (verified with `eu-stack` samples of the live RSX worker, code read):** the worker sits in
  `GuestMemory::publish_dirty_registry` → `CpuDirtyList::CpuDirtyList` (copy of every watch `shared_ptr` + `std::sort` of
  every watched span) under `watch_cpu_dirty`/`unwatch_cpu_dirty`, called from `Session::geometry_read`,
  `index_prepare`/`index_store` and the eviction of entries (`anyps3/runtime.py` `publish_dirty_registry`,
  `anyps3/rsx_graphics.py` geometry reuse block). The cache holds 512 entries; heavy views draw ~2000 draws per frame with
  more distinct spans, so the LRU thrashes (`geometry_misses` 16 397 vs `geometry_hits` 10 802 in one 2-s interval). Every
  miss evicts (unwatch → full republish) and registers (watch → full republish): tens of µs per draw. The cloud bench had
  static geometry and a small working set, so it measured only hits.
- **Bound on any reuse (derived):** with reuse off the two stages it replaces cost 0.47 + ~0.4 ms per frame (1036g1), so a
  correct reuse can save at most ~1 ms of worker time per frame.
- **Decision:** `ANYPS3_RSX_GEOMETRY_REUSE` defaults to **0** (`e3b53f3`); `=1` opts in. `test_rsx2_draw` sets its sessions'
  `geometry_reuse=true` explicitly. Same binary with `=0`: **1036g1 43.81 FPS, worker 8.87 ms**.
- **If reuse is revisited:** it needs an admission policy (cache a span only on its second sighting), capacity sized to the
  view (thousands), and a registry whose publication is O(changes), not O(n log n) — and it must beat ~1 ms/frame.

## Finding 2 — device-memory pool: teardown left blocks registered (verified, accounting only)

`release_memory_cache()` freed the blocks a device still retained at teardown without removing them from
`resource_stats()["device_memory_blocks"]` (the two other free paths did). `test_rsx_pipeline_cache` (NVIDIA: device-local
pool on by default) failed its empty-registry check; it passed on the HIRES2 base and with `ANYPS3_RSX_MEMORY_POOL=0`.
Fix `a020c8d`; `test_rsx_vk_memory_pool` now checks the registry after the device is destroyed (fails without the fix,
passes with it on lavapipe and NVIDIA). The memory itself was always freed; no game effect.

## Finding 3 — three "lavapipe cache asserts" were stale oracles since HIRES2 (verified)

`test_rsx_fp_cache`, `test_rsx_sampler_identity`, `test_rsx_resident_sampler` fail identically on NVIDIA, on the HIRES2 base
`d5d3323` and on the tip. Bisected (subagent, re-checked): `9912280` passes, `08f6930` fails; the cause is `409f8bb` (static
fragment discards), which keys the cached source by `fragment_discard_state(r)` while `fragment_source_uncached` keeps the
all-discards default; the tests compared the cached text with that default. Fix `1e45a72`: the oracles pass the same
discard state (test-only). **Refuted:** the cloud records' attribution of these to lavapipe. `test_rsx_perf_decode` and
`test_present_window` pass on the PC.

## Finding 4 — `test_rsx_residency` under GCC 16 (verified)

Its combined binary appends the graphics sub-tests by name and missed `graphics_static_discard`, so GCC 16
`-Werror=unused-function` stopped the build. Fix `72fcca2` (also runs that sub-test). `test_ppu_fp_lazy`, `test_ppuperf3`,
`test_savedata_vsh` pass with GCC 16.
